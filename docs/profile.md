# Профиль кандидата и как работает сверка

## Откуда берётся профиль

`jobhunter profile` берёт самый свежий файл из `workspace/resume/`, извлекает текст и просит LLM составить
`profile.yaml`.

| Формат | Как читается |
|---|---|
| `.pdf` | текстовый слой через `pypdf`. Сканы (картинки) не читаются — сохраните резюме как DOCX или TXT |
| `.docx` | текст абзацев документа |
| `.txt`, `.md` | как есть (UTF-8 или Windows-1251) |

Профиль — **черновик**. Модель может пропустить навык или придумать лишний — просмотрите файл перед первым запуском.

## Формат

```yaml
years:
  default: 12                    # общий профильный стаж
  areas:                         # уточнения: «опыт продакта от 3 лет» сравнивается с 2, а не с 12
    - { match: "продакт|product|продукт", years: 2 }
english: B1                      # none, A1…C2
education: { level: высшее, field: техническое, match: "техническ|информац|математ" }
skills:                          # ✅ закрыто опытом
  - { match: "\\berp\\b|1с|sap", note: "внедрение 1С:ERP на 3 заводах" }
partial:                         # 🟡 частично
  - { match: "\\bsql\\b", note: "SQL на уровне простых выборок" }
hidden:                          # 💡 есть, но в резюме не написано → подсказка дописать
  - { match: "chatgpt|\\bии\\b", note: "использую ChatGPT в работе" }
missing:                         # ❌ нет; hard: true — целой специализации нет
  - { match: "\\bml\\b|machine learning", note: "нет опыта ML", hard: true }
```

`match` — регулярное выражение по тексту требования (нижний регистр, «ё» → «е»). `note` попадает в отчёт —
пишите конкретно: цифры, проекты, годы.

## Как считается вердикт

1. Из описания вакансии вырезается блок требований («Требования», «Мы ждём», «Что важно»…). Пункты
   «будет плюсом» в процент не входят.
2. Каждое требование проверяется правилами. Если совпало несколько, побеждает самое строгое:
   `missing` → `partial` → `hidden` → `skills`. Личные качества («коммуникабельность») не считаются.
3. Английский сравнивается с уровнем `english`, стаж «от N лет» — со стажем по области, образование — с `education`.
4. «X или Y»: если провалена часть X, а альтернатива Y закрыта — требование засчитывается как частичное.
5. **Соответствие** = (✅ × 1 + 💡 × 0.75 + 🟡 × 0.5) / распознанных требований.

| Вердикт | Условие |
|---|---|
| Подходит | соответствие ≥ 75%, нет стоп-факторов и критичных пробелов |
| Частично | соответствие ≥ 50%, не больше одного критичного пробела |
| Не подходит | стоп-фактор (английский выше вашего, стаж) или ≥ 2 критичных пробела, или < 50% |
| Проверь вручную | распознано меньше 3 требований |

Пороги меняются в `config.yaml → matching`.

## Как улучшать профиль

Откройте в отчёте колонку **«Не распознано»** и лист **«Пробелы резюме»**:

- требование про то, что у вас есть, попало в «Не распознано» → добавьте правило в `skills`;
- ложный «❌» → правило в `missing` слишком широкое, сузьте шаблон;
- одно и то же «💡 дописать в резюме» встречается в десятках вакансий → допишите это в резюме.

## ИИ-судья (необязательно)

`matching.mode: hybrid` — нераспознанные правилами требования отправляются в LLM одним запросом на вакансию вместе
с кратким профилем (`summary`, навыки). Ответы кэшируются в базе, одинаковые формулировки повторно не оплачиваются.
Пояснения ИИ в отчёте начинаются с «ИИ:».
